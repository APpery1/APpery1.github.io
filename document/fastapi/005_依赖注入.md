# 005：依赖注入

> 本篇解决接口之间开始出现复制粘贴的问题。
>
> 学习目标：理解 `Depends` 在 FastAPI 里做了什么，会写普通依赖、嵌套依赖和带 `yield` 的清理依赖，并知道它为什么是后面数据库 Session、当前用户的统一入口。

---

## 一、我们要解决什么问题？

004 的列表接口已经有 `limit`、`author`、`q`。过几天再加 `GET /authors`、`GET /tags`，分页参数又要抄一遍：

```python
def list_books(limit: int = 20, offset: int = 0):
    ...

def list_authors(limit: int = 20, offset: int = 0):
    ...
```

更麻烦的是这些跨接口逻辑：

- 从 Header 取出 token，解析出当前用户。
- 打开数据库 Session，用完关闭。
- 校验 API Key。
- 写一条请求日志。

如果每个路径函数里都写，改一处要翻全项目。FastAPI 的答案是 **依赖注入**：把公共步骤写成函数，在需要的地方声明“我依赖它”，框架在调用你的接口之前先执行依赖，把结果当作参数传进来。

```text
请求进来
  ↓
执行依赖 A（可能再依赖 B）
  ↓
得到依赖返回值
  ↓
调用路径函数
  ↓
（若依赖用了 yield）先返回响应，再执行 yield 后面的清理
```

## 二、最小依赖

```python
from typing import Annotated

from fastapi import Depends, FastAPI, Query

app = FastAPI()


def pagination(
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> dict:
    return {"limit": limit, "offset": offset}


@app.get("/books")
def list_books(page: Annotated[dict, Depends(pagination)]):
    return {"page": page}
```

发生了什么：

1. `pagination` 本身也可以声明 `Query` 参数，这些参数会合并到 `GET /books` 的文档里。
2. 客户端仍然访问 `/books?limit=10&offset=20`，并不知道有依赖这回事。
3. 路径函数拿到的是 `pagination` 的返回值。

`Depends(pagination)` 括号里是**函数本身**，不是 `pagination()`。框架负责调用。

类型可以写得更清楚，避免 `dict`：

```python
from typing import NamedTuple


class Page(NamedTuple):
    limit: int
    offset: int


def pagination(
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> Page:
    return Page(limit=limit, offset=offset)


@app.get("/books")
def list_books(page: Annotated[Page, Depends(pagination)]):
    items = list(BOOKS.values())
    return items[page.offset : page.offset + page.limit]
```

## 三、依赖不一定要用返回值

有的依赖只做检查，通过就放行，失败就抛 `HTTPException`：

```python
from typing import Annotated

from fastapi import Depends, Header, HTTPException, status


def require_api_key(x_api_key: Annotated[str | None, Header()] = None) -> None:
    if x_api_key != "dev-secret":
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="无效的 API Key",
        )


@app.get("/internal/stats", dependencies=[Depends(require_api_key)])
def stats():
    return {"books": len(BOOKS)}
```

两种挂法：

| 写法 | 何时用 |
|---|---|
| 函数参数 `x: Annotated[..., Depends(fn)]` | 需要用到依赖的返回值 |
| 装饰器 `dependencies=[Depends(fn)]` | 只要副作用 / 校验，函数签名保持干净 |

`Header()` 默认把 `x_api_key` 转成请求头 `X-Api-Key`（下划线变连字符、自动处理大小写）。客户端：

```bash
curl http://127.0.0.1:8000/internal/stats -H "X-Api-Key: dev-secret"
```

密钥写死在代码里只适合演示。真正的密钥进环境变量，009 再换成 JWT。

## 四、类作为依赖

依赖也可以是可调用的类。适合内部要保存配置的情况：

```python
class RequireRole:
    def __init__(self, role: str):
        self.role = role

    def __call__(self, current_user: Annotated[dict, Depends(get_current_user)]) -> dict:
        if current_user["role"] != self.role:
            raise HTTPException(status_code=403, detail="权限不足")
        return current_user


require_admin = RequireRole("admin")


@app.delete("/books/{book_id}")
def delete_book(
    book_id: int,
    user: Annotated[dict, Depends(require_admin)],
):
    ...
```

`Depends(require_admin)` 实际调用的是实例的 `__call__`。这是 009 做“管理员才能删除”时会用的模式。现在先混个眼熟。

`get_current_user` 还没实现时，可以先写一个假的：

```python
def get_current_user() -> dict:
    return {"id": 1, "name": "demo", "role": "admin"}
```

依赖非常适合这种“先假后真”：路径函数签名不用改，只要替换 `get_current_user` 的实现。

## 五、嵌套依赖与缓存

依赖可以再依赖别的依赖：

```python
def get_settings() -> dict:
    return {"app_name": "book-api"}


def get_store(settings: Annotated[dict, Depends(get_settings)]) -> dict:
    return BOOKS


@app.get("/books/{book_id}")
def get_book(
    book_id: int,
    store: Annotated[dict, Depends(get_store)],
):
    ...
```

同一次请求里，同一个依赖函数默认 **只执行一次**。如果 `get_book` 和某个子依赖都 `Depends(get_settings)`，`get_settings` 仍只跑一遍。这叫依赖缓存，对数据库 Session、当前用户这种对象很重要：同一请求里应看到同一份 Session。

若确实要每次都执行（极少见）：

```python
Depends(get_settings, use_cache=False)
```

## 六、`yield` 依赖：用完要清理

打开资源、用完必须关掉时，把依赖写成生成器：

```python
from collections.abc import Generator


def get_db() -> Generator[dict, None, None]:
    db = {"opened": True}  # 想象这是 Session()
    try:
        yield db
    finally:
        db["opened"] = False  # 想象这是 session.close()
```

路径函数里：

```python
@app.post("/books")
def create_book(
    payload: BookCreate,
    db: Annotated[dict, Depends(get_db)],
):
    ...
```

执行顺序：

```text
1. get_db 跑到 yield，得到 db
2. 路径函数执行（成功或抛 HTTPException）
3. 响应准备好之后，finally 里的清理一定执行
```

这就是 008 里 SQLAlchemy Session 的标准写法。记住两件事：

1. `yield` 只能有一次。
2. 清理发生在**响应生成之后**。不要在清理阶段再改响应体。后台收尾、关连接、提交或回滚放这里。

异常时谁负责 rollback？常见模式：

```python
def get_db() -> Generator[Session, None, None]:
    session = SessionLocal()
    try:
        yield session
        session.commit()
    except Exception:
        session.rollback()
        raise
    finally:
        session.close()
```

有人更喜欢在路径函数里显式 `session.commit()`，依赖只负责 close。两种都成立，项目里统一即可。008 会选一种并写完。

## 七、子应用 / 路由级依赖

006 会用 `APIRouter`。依赖可以挂在三个层级：

```python
app = FastAPI(dependencies=[Depends(log_request)])

router = APIRouter(
    prefix="/books",
    dependencies=[Depends(require_api_key)],
)

@router.get("/{book_id}", dependencies=[Depends(record_hit)])
def get_book(...):
    ...
```

顺序从外到内：`app` → `router` → 路径装饰器 → 函数参数里的 `Depends`。

越公共的检查挂得越靠外。例如全站请求日志挂 `app`，图书写操作的登录检查挂 `router`，某一个接口的额外权限挂在该函数上。

## 八、把 004 的分页抽出来

```python
from typing import Annotated, NamedTuple

from fastapi import Depends, Query


class Page(NamedTuple):
    limit: int
    offset: int


def pagination(
    limit: Annotated[int, Query(ge=1, le=100, description="每页条数")] = 20,
    offset: Annotated[int, Query(ge=0, description="跳过前 N 条")] = 0,
) -> Page:
    return Page(limit, offset)
```

列表接口变成：

```python
@app.get("/books", response_model=list[BookRead])
def list_books(
    page: Annotated[Page, Depends(pagination)],
    author: Annotated[str | None, Query()] = None,
):
    items = list(BOOKS.values())
    if author:
        items = [b for b in items if b["author"] == author]
    return items[page.offset : page.offset + page.limit]
```

`author` 仍留在路径函数上，因为它是这个接口特有的筛选。`limit`/`offset` 是跨接口的，所以进依赖。

**判断标准：** 这段参数或这段逻辑会不会被第二个接口用到？会，就抽依赖。不会，就留在函数里。不要为了“看起来高级”把所有参数都塞进 Depends。

## 九、常见误区

### 1. 写了 `Depends(pagination())`

多了一对括号，传进去的是返回值而不是可调用对象，启动或请求时会报错。正确：`Depends(pagination)`。

### 2. 在依赖里做很重的同步阻塞

依赖和路径函数跑在同一次请求处理中。里面如果 `time.sleep(3)` 或同步打远程 HTTP，表现和把代码写在路径函数里一样差。该 async 就 async：

```python
async def get_remote_user():
    async with httpx.AsyncClient() as client:
        ...
```

路径函数若是普通 `def`，仍然可以 `Depends` 一个 `async def` 依赖，FastAPI 会 await 它。反过来也行。不必为了依赖把所有接口改成 async。

### 3. 把业务规则全塞进依赖

依赖适合 **基础设施**（鉴权、Session、分页、公共 Header）。“这本书是否允许这个用户编辑”这种业务判断，放在 service 函数里更可读。依赖不是新的上帝对象。

### 4. 循环依赖

A 依赖 B，B 依赖 A，启动或请求时会出问题。保持单向：`get_settings` → `get_db` → `get_current_user` → 路径函数。

## 十、本篇小结

依赖注入的最小形状：

```python
def pagination(limit: int = 20, offset: int = 0) -> Page:
    return Page(limit, offset)

@app.get("/books")
def list_books(page: Annotated[Page, Depends(pagination)]):
    ...
```

需要掌握的核心概念：

- `Depends(函数)` 在路径函数之前执行，结果作为参数注入。
- 依赖自己也可以声明 Query / Header / 其它 Depends。
- 只要副作用时用装饰器上的 `dependencies=[...]`。
- 同一请求内同一依赖默认只跑一次。
- `yield` 依赖负责打开/关闭资源，是数据库 Session 的标准入口。
- 假的 `get_current_user` 可以先占位，以后替换实现而不改接口签名。

下一篇把单文件拆成包：`routers`、`schemas`、`deps`。依赖函数会放到 `deps.py`，这是真实项目里它该在的位置。
