# 006：路由拆分与项目结构

> 本篇把 004 的单文件 CRUD 拆成一个可以继续长的项目。
>
> 学习目标：会用 `APIRouter`、`include_router`、`prefix` 和 `tags`，并建立一个小而完整的目录约定。

---

## 一、我们要解决什么问题？

单文件在学习前四篇很合适。一旦加上用户、登录、数据库，`main.py` 会变成几百行的“什么都往里扔”。后端常见的拆法是按**职责**分层，而不是按技术名词堆文件夹。

我们要达到的效果：

- 新增一个资源（例如作者）时，主要是加一个 router 文件，而不是改 `main.py` 里的一长串装饰器。
- 模型、依赖、业务、入口各在各的地方。
- `uvicorn` 启动命令仍然简单。

FastAPI 提供的拼装单位是 `APIRouter`：它长得像缩小版的 `app`，可以声明自己的前缀、标签、依赖，最后挂到真正的 `FastAPI()` 上。

---

## 二、推荐的最小目录

```text
book_api/
├── app/
│   ├── __init__.py
│   ├── main.py              # 只创建 app、挂路由、挂中间件
│   ├── deps.py              # 可复用 Depends
│   ├── schemas/
│   │   ├── __init__.py
│   │   └── book.py          # Pydantic 模型
│   ├── routers/
│   │   ├── __init__.py
│   │   └── books.py         # 路径操作函数
│   └── services/
│       ├── __init__.py
│       └── book_service.py  # 业务与内存/数据库操作
├── tests/
└── README.md
```

先不用纠结 `models`（ORM）和 `schemas`（Pydantic）的名字。008 加数据库时会新增 `app/models/` 放 SQLAlchemy 模型，和 Pydantic schema 分开。现在没有数据库，service 里用字典即可。

为什么不把 CRUD 直接写在 router 里？可以，很多教程也这么做。项目稍大之后，同一个“创建图书”会被 HTTP 接口和以后的脚本、定时任务共用，service 层就有价值。学习阶段 service 可以很薄，甚至只是对 `BOOKS` 字典的封装。

启动方式改为：

```bash
uvicorn app.main:app --reload
```

注意模块路径是 `app.main:app`，要在 `book_api/` 这一层启动，而不是进到 `app/` 里面再启动，否则包导入会乱。

## 三、`APIRouter` 怎么写？

`app/routers/books.py`：

```python
from typing import Annotated

from fastapi import APIRouter, Depends, HTTPException, Path, Query, Response, status

from app.deps import pagination, Page
from app.schemas.book import BookCreate, BookRead, BookUpdate
from app.services import book_service

router = APIRouter(prefix="/books", tags=["books"])


@router.get("", response_model=list[BookRead])
def list_books(
    page: Annotated[Page, Depends(pagination)],
    author: Annotated[str | None, Query()] = None,
    q: Annotated[str | None, Query(min_length=1, max_length=50)] = None,
):
    return book_service.list_books(author=author, q=q, page=page)


@router.get("/{book_id}", response_model=BookRead)
def get_book(book_id: Annotated[int, Path(ge=1)]):
    book = book_service.get_book(book_id)
    if book is None:
        raise HTTPException(status_code=404, detail="未找到图书")
    return book


@router.post("", response_model=BookRead, status_code=status.HTTP_201_CREATED)
def create_book(payload: BookCreate):
    try:
        return book_service.create_book(payload)
    except book_service.DuplicateTitleError:
        raise HTTPException(status_code=409, detail="书名已存在")


@router.put("/{book_id}", response_model=BookRead)
def replace_book(book_id: Annotated[int, Path(ge=1)], payload: BookCreate):
    book = book_service.replace_book(book_id, payload)
    if book is None:
        raise HTTPException(status_code=404, detail="未找到图书")
    return book


@router.patch("/{book_id}", response_model=BookRead)
def patch_book(book_id: Annotated[int, Path(ge=1)], payload: BookUpdate):
    book = book_service.patch_book(book_id, payload)
    if book is None:
        raise HTTPException(status_code=404, detail="未找到图书")
    return book


@router.delete("/{book_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_book(book_id: Annotated[int, Path(ge=1)]):
    ok = book_service.delete_book(book_id)
    if not ok:
        raise HTTPException(status_code=404, detail="未找到图书")
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

和写在 `app` 上的唯一表面差别：`@app.get` 换成 `@router.get`。

`prefix="/books"` 之后，装饰器里写 `""`、`"/{book_id}"` 即可，不要再写 `"/books"`，否则实际路径会变成 `/books/books`。

`tags=["books"]` 只影响 `/docs` 的分组标题，不影响 URL。不同 router 用不同 tag，文档会按资源折叠。

## 四、在 `main.py` 里挂上

`app/main.py` 应当很短：

```python
from fastapi import FastAPI

from app.routers import books

app = FastAPI(title="图书管理 API", version="0.6.0")

app.include_router(books.router)


@app.get("/health", tags=["meta"])
def health():
    return {"status": "ok"}
```

`include_router` 还可以再加一层前缀，适合以后做 API 版本：

```python
app.include_router(books.router, prefix="/api/v1")
```

最终路径会是：

```text
router.prefix + include_router.prefix + 装饰器路径
/books        + /api/v1                + /{book_id}
→ /api/v1/books/{book_id}
```

本系列暂不加 `/api/v1`，少一层心智负担。真要做版本，建议一开始就加，而不是上线后再改 URL。

同一个 router 也可以挂两次（极少见，例如兼容旧路径）。普通项目一次 `include_router` 足够。

## 五、schemas 和 deps

`app/schemas/book.py` 就是 004 里的三个模型，原样搬过来：

```python
from pydantic import BaseModel, Field, field_validator


class BookCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    author: str = Field(min_length=1, max_length=50)
    year: int = Field(ge=1400, le=2100)
    price: float = Field(gt=0)

    @field_validator("title", "author")
    @classmethod
    def strip_text(cls, value: str) -> str:
        stripped = value.strip()
        if not stripped:
            raise ValueError("不能为空")
        return stripped


class BookUpdate(BaseModel):
    title: str | None = Field(default=None, min_length=1, max_length=100)
    author: str | None = Field(default=None, min_length=1, max_length=50)
    year: int | None = Field(default=None, ge=1400, le=2100)
    price: float | None = Field(default=None, gt=0)


class BookRead(BaseModel):
    id: int
    title: str
    author: str
    year: int
    price: float
```

`app/deps.py`：

```python
from typing import Annotated, NamedTuple

from fastapi import Query


class Page(NamedTuple):
    limit: int
    offset: int


def pagination(
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> Page:
    return Page(limit, offset)
```

依赖集中放 `deps.py`（或以后拆 `deps/auth.py`），router 不要互相 import 对方的依赖函数，避免环。

## 六、薄薄的 service

`app/services/book_service.py`：

```python
from app.deps import Page
from app.schemas.book import BookCreate, BookUpdate

BOOKS: dict[int, dict] = {}
_next_id = 1


class DuplicateTitleError(Exception):
    pass


def list_books(author: str | None, q: str | None, page: Page) -> list[dict]:
    items = list(BOOKS.values())
    if author:
        items = [b for b in items if b["author"] == author]
    if q:
        items = [b for b in items if q in b["title"]]
    return items[page.offset : page.offset + page.limit]


def get_book(book_id: int) -> dict | None:
    return BOOKS.get(book_id)


def create_book(payload: BookCreate) -> dict:
    global _next_id
    if any(b["title"] == payload.title for b in BOOKS.values()):
        raise DuplicateTitleError
    book = {"id": _next_id, **payload.model_dump()}
    BOOKS[_next_id] = book
    _next_id += 1
    return book


def replace_book(book_id: int, payload: BookCreate) -> dict | None:
    if book_id not in BOOKS:
        return None
    book = {"id": book_id, **payload.model_dump()}
    BOOKS[book_id] = book
    return book


def patch_book(book_id: int, payload: BookUpdate) -> dict | None:
    stored = BOOKS.get(book_id)
    if stored is None:
        return None
    stored.update(payload.model_dump(exclude_unset=True))
    return stored


def delete_book(book_id: int) -> bool:
    if book_id not in BOOKS:
        return False
    del BOOKS[book_id]
    return True
```

这里用 `DuplicateTitleError` 而不是在 service 里 `raise HTTPException`，是为了让 service **不依赖 FastAPI**。以后写脚本导入 `create_book` 时，不应该突然出现 HTTP 层概念。router 负责把领域异常翻译成状态码。

这是一条值得坚持的边界：

```text
router：HTTP（参数、状态码、依赖）
service：业务（能不能创建、怎么改数据）
schema：数据形状
deps：请求级基础设施
```

## 七、`tags`、`summary`、`response` 文档小技巧

```python
@router.get(
    "/{book_id}",
    response_model=BookRead,
    summary="获取一本图书",
    responses={404: {"description": "图书不存在"}},
)
```

- `summary`：文档列表里的短标题，默认是函数名转空格。
- `responses`：补上 `response_model` 不会自动体现的错误码，联调的人能在文档里看到 404。
- 函数 docstring 会出现在接口详情里，可以写注意事项。

不要为了文档把注释写成长篇小说。接口行为以代码为准，文档只补代码看不出来的约定。

## 八、再加一个 router 时怎么做？

例如健康检查也可以搬走，或新增作者：

```python
# app/routers/authors.py
from fastapi import APIRouter

router = APIRouter(prefix="/authors", tags=["authors"])


@router.get("")
def list_authors():
    return []
```

`main.py` 增加一行：

```python
from app.routers import authors, books

app.include_router(books.router)
app.include_router(authors.router)
```

`main.py` 保持“目录”角色，不堆业务。这就是拆 router 的收益。

## 九、导入习惯

在 `book_api/` 根目录运行时，`app` 是包。一律用绝对导入：

```python
from app.schemas.book import BookRead
from app.deps import pagination
```

不要写 `from schemas.book import ...`，也不要改 `sys.path`。测试、Uvicorn、以后的 Docker 工作目录都应以项目根为准。

`app/__init__.py` 可以是空文件。不要在 `__init__.py` 里创建 `app` 实例，以免循环导入：`main` import `routers`，`routers` import `app` 包时又执行创建逻辑。

## 十、本篇小结

拆分之后的组装方式：

```python
router = APIRouter(prefix="/books", tags=["books"])
app.include_router(router)
```

需要掌握的核心概念：

- `APIRouter` 是一组路径的容器，不是又一个服务器。
- `prefix` 拼 URL，`tags` 只影响文档分组。
- `main.py` 只负责创建 `app` 和挂载。
- schema / router / service / deps 按职责分，而不是按“文件别太大”随便切。
- service 不要抛 `HTTPException`，让 router 翻译。
- 启动命令在项目根：`uvicorn app.main:app --reload`。

下一篇处理横切能力：统一异常格式、CORS、自定义中间件。它们通常也挂在 `main.py`，但不应把业务写进去。
