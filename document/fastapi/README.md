# FastAPI 学习文档

> 面向已经具备 Python 基础的同学。目标不是把官方文档再抄一遍，而是按真实后端开发顺序，把 FastAPI 里每天都会用到的部分讲清楚。
>
> 写法对齐同目录下的 LangChain 学习文档：一篇只解决一类问题，先讲“为什么”，再讲“怎么写”，最后用小结收住。

---

## 怎么学

1. 按编号顺序读，后面的篇会引用前面的概念。
2. 每一篇都有可直接运行的最小示例，建议自己敲一遍，不要只看。
3. 贯穿全文的练习项目是一个**图书管理 API**：从返回 JSON，逐步加参数、模型、路由、数据库和登录。
4. 环境建议：Python 3.10+。类型注解会大量使用 `str | None` 这种写法。

安装一次即可：

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
# source .venv/bin/activate

pip install "fastapi[standard]"
```

`fastapi[standard]` 会带上运行服务用的 `uvicorn`，以及开发时自动重载、校验相关的依赖。

启动任意一篇里的 `main.py`：

```bash
uvicorn main:app --reload
```

浏览器打开：

- 接口本身：<http://127.0.0.1:8000>
- 交互文档：<http://127.0.0.1:8000/docs>
- 另一种文档：<http://127.0.0.1:8000/redoc>
- OpenAPI 描述：<http://127.0.0.1:8000/openapi.json>

## 贯穿项目：图书管理 API

后面章节会反复用到这组接口，字段会逐渐变完整：

```text
GET    /books          列表（可按作者、关键词筛选）
GET    /books/{book_id} 详情
POST   /books          新增
PUT    /books/{book_id} 全量更新
PATCH  /books/{book_id} 部分更新
DELETE /books/{book_id} 删除
POST   /auth/login     登录（009 起）
```

一本图书在业务里大致长这样：

```json
{
  "id": 1,
  "title": "FastAPI 入门",
  "author": "张三",
  "year": 2024,
  "price": 59.0
}
```

001 先返回一句问候；002 开始按 id 查书；003 开始用模型接 POST；008 才真正写入数据库。中间用内存字典模拟存储，是为了先把 HTTP 和 FastAPI 本身学扎实。

## 和 Flask / Django 差在哪（先有个印象）

| | FastAPI | Flask | Django |
|---|---|---|---|
| 定位 | API 优先 | 微框架 | 全功能 Web |
| 参数校验 | 类型注解 + Pydantic，自动做 | 通常自己写或靠扩展 | Form/Serializer |
| 文档 | 自动生成 OpenAPI / Swagger | 需扩展 | 需扩展 |
| 异步 | 原生 ASGI | 传统 WSGI，异步是后加的 | 逐步支持 ASGI |
| 适合 | 后端 API、微服务、给前端/移动端提供 JSON | 小服务、快速脚本 | 带管理后台的整站 |

有 Python 基础后，FastAPI 最需要建立的习惯是：**函数参数的类型注解不是装饰，而是接口契约。** 框架靠它生成校验、文档和解析逻辑。

## 学习时常见卡点

- 分不清路径参数、查询参数、请求体：先读 002、003。
- `422 Unprocessable Entity`：几乎一定是请求数据和模型对不上，打开 `/docs` 对照。
- 改了代码没生效：确认用了 `--reload`，且改的是正在运行的那个文件。
- `def` 和 `async def` 混用：001 会说明，业务代码里先统一一种即可。
- 依赖循环、数据库 Session 没关闭：005 和 008 专门处理。

读完 010 之后，你应当能独立搭一个带登录、带数据库、带测试的小型 FastAPI 服务。
