# 009：认证与授权

> 本篇让“谁都能改书库”变成“先登录，再带着令牌访问写接口”。
>
> 学习目标：分清认证和授权，理解密码哈希、JWT、`OAuth2PasswordBearer`，并用依赖保护路由。

---

## 一、我们要解决什么问题？

HTTP 默认是无状态的：服务器不会因为你刚才 POST 成功了，就记住浏览器是“张三”。每次请求都要重新证明身份。

两件不同的事：

| 词 | 问题 | 本篇做法 |
|---|---|---|
| 认证 Authentication | 你是谁？ | 用户名+密码换 JWT |
| 授权 Authorization | 你能做什么？ | 依赖里看 `role`，管理员才能删除 |

不要把 JWT 想成加密传输。它是一份**带签名的声明**：服务器能确认没被篡改，内容本身通常只是 Base64，谁拿到谁就能用。因此 JWT 要走 HTTPS，不要放进 URL，不要写进前端仓库。

本篇用最常见的 API 方案：

```text
POST /auth/login   用户名密码 → access_token
之后的写接口        Header: Authorization: Bearer <token>
get_current_user   解码 token，查出用户
```

安装：

```bash
pip install "pwdlib[argon2]" PyJWT
```

`pwdlib` 用来哈希密码。官方文档曾经用 `passlib`，现在更推荐 pwdlib。`PyJWT` 负责签发和校验 JWT。不要自己用 `hashlib.md5` 存密码。

## 二、密码绝不能明文存

用户表只存哈希：

```python
from pwdlib import PasswordHash

password_hash = PasswordHash.recommended()

hashed = password_hash.hash("明文密码")
ok = password_hash.verify("明文密码", hashed)
```

`hash()` 每次结果不同（带随机盐），所以不能用 `==` 比较两次哈希，必须 `verify`。

ORM 增加用户：

```python
# app/models/user.py
from sqlalchemy import String, Integer
from sqlalchemy.orm import Mapped, mapped_column

from app.db import Base


class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    username: Mapped[str] = mapped_column(String(50), unique=True, nullable=False)
    hashed_password: Mapped[str] = mapped_column(String(255), nullable=False)
    role: Mapped[str] = mapped_column(String(20), default="user", nullable=False)
```

对外 schema **没有** `hashed_password`：

```python
class UserRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    username: str
    role: str


class UserCreate(BaseModel):
    username: str = Field(min_length=3, max_length=50)
    password: str = Field(min_length=6, max_length=50)
```

这就是 003 强调拆模型的原因：出口一旦用错 `User` ORM，密码哈希就泄漏了。

## 三、JWT 里放什么？

一份 JWT 有三段：`header.payload.signature`。payload 示例：

```json
{
  "sub": "1",
  "exp": 1730000000
}
```

- `sub`：subject，通常放用户 id。
- `exp`：过期时间，校验库会检查。

不要把权限列表、身份证号塞满 payload。token 会发到客户端，用户能解码看到（改不了，除非有密钥）。权限以服务端当时查到的为准，否则你改了数据库角色，旧 token 在过期前仍冒充管理员。

签发与校验：

```python
# app/security.py
from datetime import datetime, timedelta, timezone

import jwt
from pwdlib import PasswordHash

SECRET_KEY = "请换成环境变量里的长随机串"
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 60

password_hash = PasswordHash.recommended()


def hash_password(plain: str) -> str:
    return password_hash.hash(plain)


def verify_password(plain: str, hashed: str) -> bool:
    return password_hash.verify(plain, hashed)


def create_access_token(user_id: int) -> str:
    expire = datetime.now(timezone.utc) + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    payload = {"sub": str(user_id), "exp": expire}
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)


def parse_access_token(token: str) -> int:
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        sub = payload.get("sub")
        if sub is None:
            raise ValueError("missing sub")
        return int(sub)
    except (jwt.PyJWTError, ValueError) as exc:
        raise ValueError("invalid token") from exc
```

`SECRET_KEY` 必须来自环境变量，长度要够。泄漏等于任何人能给自己签发管理员 token。`algorithms=[ALGORITHM]` 必须显式传入，避免算法混淆攻击。

## 四、登录接口

OAuth2 密码模式要求客户端用 **表单** 提交 `username`、`password`，不是 JSON。这是协议规定，Swagger 的 Authorize 按钮也按这个走。

```python
# app/routers/auth.py
from fastapi import APIRouter, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordRequestForm
from sqlalchemy.orm import Session

from app.deps import get_db
from app.schemas.token import Token
from app.services import user_service

router = APIRouter(prefix="/auth", tags=["auth"])


@router.post("/login", response_model=Token)
def login(
    form: OAuth2PasswordRequestForm = Depends(),
    db: Session = Depends(get_db),
):
    user = user_service.authenticate(db, form.username, form.password)
    if user is None:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="用户名或密码错误",
            headers={"WWW-Authenticate": "Bearer"},
        )
    token = user_service.issue_token(user)
    return {"access_token": token, "token_type": "bearer"}
```

`OAuth2PasswordRequestForm` 会从 form 里取 `username`、`password`。自己用 Pydantic JSON 登录也能工作，但 `/docs` 右上角 Authorize 不会自动适配。学习阶段跟协议走。

`Token` schema：

```python
class Token(BaseModel):
    access_token: str
    token_type: str = "bearer"
```

`authenticate`：按用户名查，`verify_password`，失败返回 `None`。不要在报错里区分“用户不存在”和“密码错误”，减少被枚举用户名的机会。

注册接口可以 `POST /auth/register`，body 用 `UserCreate`。演示项目也可在 lifespan 里种一个管理员：

```python
# 仅开发用
if not user_service.get_by_username(db, "admin"):
    user_service.create_user(db, "admin", "admin123", role="admin")
```

## 五、`get_current_user`：保护接口的钥匙

```python
# app/deps.py
from typing import Annotated

from fastapi import Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer
from sqlalchemy.orm import Session

from app.db import get_db as _get_db
from app.models.user import User
from app.security import parse_access_token
from app.services import user_service

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/login")

DbSession = Annotated[Session, Depends(_get_db)]


def get_current_user(
    token: Annotated[str, Depends(oauth2_scheme)],
    db: DbSession,
) -> User:
    credentials_exc = HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="无效的认证信息",
        headers={"WWW-Authenticate": "Bearer"},
    )
    try:
        user_id = parse_access_token(token)
    except ValueError:
        raise credentials_exc
    user = user_service.get_by_id(db, user_id)
    if user is None:
        raise credentials_exc
    return user


CurrentUser = Annotated[User, Depends(get_current_user)]
```

`OAuth2PasswordBearer` 做两件事：

1. 从 Header `Authorization: Bearer <token>` 取出 token，没有就 401。
2. 告诉 OpenAPI：本 API 使用 OAuth2 密码流，token 去 `tokenUrl` 拿。于是 `/docs` 出现 Authorize 按钮。

`tokenUrl` 是文档用的相对路径，要和真实登录路径一致。

读接口可以不登录，写接口必须登录：

```python
@router.get("", response_model=list[BookRead])
def list_books(...):
    ...


@router.post("", response_model=BookRead, status_code=201)
def create_book(payload: BookCreate, db: DbSession, user: CurrentUser):
    ...
```

`user` 暂时可以不用，光声明就能拦住未登录请求。需要记录“谁创建的”时，用 `user.id` 写入 `created_by` 字段。

整组写操作都要登录时，挂在 router 上更省事：

```python
write_router = APIRouter(
    prefix="/books",
    tags=["books"],
    dependencies=[Depends(get_current_user)],
)
```

但 GET 若在同一个 router，会被一起保护。可以拆成 `books_public.py` / `books_write.py`，或只在写方法上声明 `CurrentUser`。本篇采用后者，更直观。

## 六、授权：角色

```python
def require_admin(user: CurrentUser) -> User:
    if user.role != "admin":
        raise HTTPException(status_code=403, detail="需要管理员权限")
    return user


AdminUser = Annotated[User, Depends(require_admin)]


@router.delete("/{book_id}", status_code=204)
def delete_book(book_id: int, db: DbSession, admin: AdminUser):
    ...
```

401 和 403 不要混用：

- 没带 token / token 无效 → **401**
- 身份有效但角色不够 → **403**

`require_admin` 依赖 `get_current_user`，同一请求里用户只解析一次（005 的依赖缓存）。

## 七、前端怎么带令牌？

登录成功后保存 `access_token`，之后：

```http
GET /books/1 HTTP/1.1
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

在 `/docs` 中：Authorize → 填登录得到的 username/password（密码模式会替你调 `/auth/login`）或直接贴 access token。之后 Try it out 会自动加 Header。

curl：

```bash
curl -X POST http://127.0.0.1:8000/auth/login ^
  -H "Content-Type: application/x-www-form-urlencoded" ^
  -d "username=admin&password=admin123"

curl -X POST http://127.0.0.1:8000/books ^
  -H "Authorization: Bearer 这里填token" ^
  -H "Content-Type: application/json" ^
  -d "{\"title\":\"FastAPI 入门\",\"author\":\"张三\",\"year\":2024,\"price\":59}"
```

## 八、常见误区

### 1. 把 JWT 当 Session 存储

服务端通常不保存 access token。注销的真正含义是客户端扔掉它。需要“立刻作废”时，要引入 refresh token 黑名单或短过期时间。学习项目把过期时间设短一些（15–60 分钟）即可。

### 2. 在 token 里信任 role

前面说过：角色以数据库为准。`get_current_user` 每次查库，看起来多一次查询，换来改角色立刻生效。

### 3. CORS + 把 token 放 Cookie

Cookie 会碰到 CSRF。API 用 Bearer Header 是更省心的默认。不要为了“看起来像网站登录”把 JWT 塞进 Cookie，除非你清楚 CSRF 怎么防。

### 4. `/docs` 被全局鉴权挡住

`app = FastAPI(dependencies=[Depends(get_current_user)])` 会让文档自己都打不开。鉴权挂在业务 router 上，不要挂在整个 app 上。

### 5. 登录成功却 422

多半是用 JSON 调了期望表单的 `/login`。Content-Type 必须是 `application/x-www-form-urlencoded`，字段名是 `username`、`password`。

## 十、本篇小结

保护一个写接口：

```python
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/login")

def get_current_user(token: Annotated[str, Depends(oauth2_scheme)], db: DbSession) -> User:
    ...

@router.post("/books")
def create_book(payload: BookCreate, user: CurrentUser, db: DbSession):
    ...
```

需要掌握的核心概念：

- 认证回答你是谁，授权回答你能不能做。
- 密码只存哈希，用 `verify` 校验。
- JWT 是带签名的声明，密钥绝不能泄漏，payload 不要塞敏感字段。
- `OAuth2PasswordBearer` 从 Authorization Header 取 token，并接通 /docs 的 Authorize。
- 登录用表单字段 `username`/`password`。
- 没登录 401，没权限 403。
- 用依赖保护路由，不要用全局中间件误伤文档和健康检查。
