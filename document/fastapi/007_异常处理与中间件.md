# 007：异常处理与中间件

> 本篇处理所有接口都会碰到、但不属于某一个业务函数的事情：错误长什么样、跨域、请求日志。
>
> 学习目标：会抛也会捕获异常，会挂 CORS，理解中间件和依赖的差别，并给图书 API 配上统一错误 JSON。

---

## 一、我们要解决什么问题？

默认情况下：

- `HTTPException(404, "未找到图书")` 返回 `{"detail": "未找到图书"}`
- Pydantic 校验失败返回 `{"detail": [ {loc, msg, type, input}, ... ]}`
- 没接住的 `ZeroDivisionError` 返回 `{"detail": "Internal Server Error"}`，终端里有 traceback

前端同事很难为三种形状写同一套错误处理。另外浏览器从 `http://localhost:5173` 访问 `http://127.0.0.1:8000` 会被同源策略拦住，这和 FastAPI 业务无关，但必须在后端放行。

这两件事都是**横切**：不是 `create_book` 该操心的。FastAPI 提供：

| 机制 | 解决什么 |
|---|---|
| `HTTPException` | 单个接口主动失败 |
| `exception_handler` | 某类异常如何变成响应 |
| 中间件 middleware | 每个请求进出时包一层 |
| CORS 中间件 | 浏览器跨域 |
| 依赖 Depends | 需要注入值或按路由挂载的检查 |

中间件更外，依赖更内。先看异常。

---

## 二、继续用 `HTTPException`

006 的 router 已经在用：

```python
raise HTTPException(status_code=404, detail="未找到图书")
```

还可以带响应头，例如 401 时常带 `WWW-Authenticate`：

```python
raise HTTPException(
    status_code=401,
    detail="未登录",
    headers={"WWW-Authenticate": "Bearer"},
)
```

`detail` 用字符串足够。如果想给前端错误码：

```python
raise HTTPException(
    status_code=409,
    detail={"code": "DUPLICATE_TITLE", "message": "书名已存在"},
)
```

默认响应仍包在 `{"detail": ...}` 里。要彻底改掉这个外壳，用自定义 handler。

## 三、统一错误响应

约定前端始终收到：

```json
{
  "code": "NOT_FOUND",
  "message": "未找到图书",
  "details": null
}
```

在 `app/exceptions.py`：

```python
from fastapi import FastAPI, HTTPException, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse


class AppError(Exception):
    def __init__(self, code: str, message: str, status_code: int = 400):
        self.code = code
        self.message = message
        self.status_code = status_code


def register_exception_handlers(app: FastAPI) -> None:
    @app.exception_handler(AppError)
    async def app_error_handler(request: Request, exc: AppError):
        return JSONResponse(
            status_code=exc.status_code,
            content={"code": exc.code, "message": exc.message, "details": None},
        )

    @app.exception_handler(HTTPException)
    async def http_exception_handler(request: Request, exc: HTTPException):
        message = exc.detail if isinstance(exc.detail, str) else "请求失败"
        return JSONResponse(
            status_code=exc.status_code,
            content={"code": "HTTP_ERROR", "message": message, "details": exc.detail},
            headers=getattr(exc, "headers", None),
        )

    @app.exception_handler(RequestValidationError)
    async def validation_handler(request: Request, exc: RequestValidationError):
        return JSONResponse(
            status_code=422,
            content={
                "code": "VALIDATION_ERROR",
                "message": "请求参数校验失败",
                "details": exc.errors(),
            },
        )

    @app.exception_handler(Exception)
    async def unhandled_handler(request: Request, exc: Exception):
        # 生产环境不要把 str(exc) 直接返回给客户端
        return JSONResponse(
            status_code=500,
            content={
                "code": "INTERNAL_ERROR",
                "message": "服务器内部错误",
                "details": None,
            },
        )
```

`main.py`：

```python
from app.exceptions import register_exception_handlers

app = FastAPI(title="图书管理 API")
register_exception_handlers(app)
```

说明：

1. `RequestValidationError` 是 422 的类型。不单独捕获的话，会被你写的 `HTTPException` 或兜底 `Exception` 搅乱格式。
2. 兜底 `Exception` 一定要写，且 **不要把内部异常信息返回给用户**。日志里记 traceback，响应里只说内部错误。
3. handler 写成 `async def` 是官方示例习惯，即使里面没有 await。
4. 捕获了 `Exception` 之后，调试期在终端仍能看到 traceback 取决于 Uvicorn / 你是否还打日志。建议在 handler 里 `logging.exception(...)`。

service 可以抛 `AppError("DUPLICATE_TITLE", "书名已存在", 409)`，router 不再手写 HTTPException。两种风格选一种即可。混合时也没问题，因为两种 handler 都注册了。

## 四、中间件：请求的洋葱圈

中间件包在整个应用外面：

```text
请求 → 中间件1 前半 → 中间件2 前半 → 路由/依赖/函数
                                         ↓
响应 ← 中间件1 后半 ← 中间件2 后半 ← 返回值编码
```

自定义中间件最简单的写法：

```python
import time
import logging

from fastapi import FastAPI, Request

logger = logging.getLogger("book_api")
app = FastAPI()


@app.middleware("http")
async def log_requests(request: Request, call_next):
    start = time.perf_counter()
    response = await call_next(request)
    cost_ms = (time.perf_counter() - start) * 1000
    logger.info(
        "%s %s → %s (%.1f ms)",
        request.method,
        request.url.path,
        response.status_code,
        cost_ms,
    )
    response.headers["X-Process-Time-Ms"] = f"{cost_ms:.1f}"
    return response
```

`call_next(request)` 会继续往后走，包括其它中间件和路径函数。你必须 `await` 它，也必须把 `response` 返回，否则客户端挂起。

适合放中间件的事：

- 请求耗时
- 统一请求 ID（从 Header 读 `X-Request-ID`，没有就生成）
- 简单的全站 Header

不适合放中间件的事：

- 解析 JSON body 后再做业务判断（body 流只能安全读一次，容易踩坑）
- 需要声明 Query 参数并出现在文档里（用 Depends）
- 只对部分路由生效的鉴权（用 router 级 Depends，否则 `/docs`、`/health` 也被拦住）

## 五、CORS

浏览器的同源策略：页面在 `http://localhost:5173`，JS 去请求 `http://127.0.0.1:8000`，默认不允许读响应。这不是 Python 错误，是浏览器行为。curl、Postman、服务器之间的调用 **没有** 这个问题。

后端通过 CORS 响应头告诉浏览器：我允许这个 Origin。

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

注意：

| 参数 | 建议 |
|---|---|
| `allow_origins` | 写明前端地址，不要图省事用 `*` 还同时 `allow_credentials=True`（这是非法组合） |
| `allow_credentials` | 前端要带 cookie 才开。JWT 放 Authorization Header 时通常可以 False |
| `allow_methods` | 开发可用 `*`，生产可收紧为实际方法 |
| `allow_headers` | 自定义头（如 `X-Api-Key`）必须允许 |

`add_middleware` 的注册顺序是**后注册的更靠外**。一般 CORS 先加或后加都能工作；和鉴权中间件共存时，确保预检请求 `OPTIONS` 不会被鉴权 401。用 CORSMiddleware 时它会处理 OPTIONS，通常没问题。把登录检查放 Depends 而不是中间件，`/docs` 和 OPTIONS 更不容易被误伤。

## 六、`lifespan`：启动和关闭

老代码里能看到：

```python
@app.on_event("startup")
async def startup():
    ...

@app.on_event("shutdown")
async def shutdown():
    ...
```

这已经过时。现在用 `lifespan`：

```python
from contextlib import asynccontextmanager

from fastapi import FastAPI


@asynccontextmanager
async def lifespan(app: FastAPI):
    # 启动：连数据库、加载缓存、创建线程池
    print("startup")
    yield
    # 关闭：断连接、刷日志
    print("shutdown")


app = FastAPI(title="图书管理 API", lifespan=lifespan)
```

`yield` 之前对应启动，之后对应关闭。Uvicorn 收到 Ctrl+C 时会走后半段。008 可以把建表、engine 的 dispose 放在这里。

不要在模块顶层做网络连接。导入 `app.main` 时就连数据库，会导致测试收集、多 worker 启动时出现意外副作用。启动期副作用放进 lifespan。

## 七、Request 对象

偶尔需要原始请求：

```python
from fastapi import Request


@router.get("/debug/headers")
def debug_headers(request: Request):
    return {
        "path": request.url.path,
        "client": request.client.host if request.client else None,
        "user_agent": request.headers.get("user-agent"),
    }
```

把 `Request` 声明为参数即可注入，不必 `Depends`。能用类型注解表达的参数，仍然优先用 Query/Path/Body，不要什么都从 `request.query_params` 里掏——那样没有校验和文档。

读取 body：`await request.body()` / `await request.json()`。一旦路径函数还声明了 Pydantic 模型，框架已经读过 body，你再读可能是空的或需要 `request.stream()` 的特殊处理。学习阶段：**body 交给模型，Request 只用来看头和 URL。**

## 八、挂到现有项目上的 `main.py`

```python
from contextlib import asynccontextmanager

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from app.exceptions import register_exception_handlers
from app.routers import books


@asynccontextmanager
async def lifespan(app: FastAPI):
    yield


def create_app() -> FastAPI:
    app = FastAPI(title="图书管理 API", version="0.7.0", lifespan=lifespan)
    register_exception_handlers(app)
    app.add_middleware(
        CORSMiddleware,
        allow_origins=["http://localhost:5173"],
        allow_credentials=False,
        allow_methods=["*"],
        allow_headers=["*"],
    )
    app.include_router(books.router)

    @app.get("/health", tags=["meta"])
    def health():
        return {"status": "ok"}

    return app


app = create_app()
```

抽 `create_app()` 是为了 010 的测试可以每次造一个干净应用，也可以在测试里关掉 CORS、换成别的配置。

## 九、依赖 vs 中间件，怎么选？

| | 依赖 | 中间件 |
|---|---|---|
| 作用范围 | 某个路由、某组路由、或函数参数 | 整个 app（除非自己写过滤） |
| 能出现在文档里 | 能（Query/Header 会显示） | 不能 |
| 能注入返回值 | 能 | 不能，只能改 Request/Response |
| 典型用途 | 登录用户、DB Session、分页 | CORS、HTTPS 跳转、全站日志、请求 ID |

鉴权用依赖，不要用中间件——否则文档页、健康检查、静态文件都要写白名单。这是从教学项目到线上项目最值得提前养成的习惯。

## 十、本篇小结

统一错误 + CORS 的骨架：

```python
register_exception_handlers(app)
app.add_middleware(CORSMiddleware, allow_origins=["http://localhost:5173"], ...)
```

需要掌握的核心概念：

- `HTTPException` 表达已知的业务/HTTP 失败。
- `exception_handler` 把各类异常压成同一种 JSON。
- 未处理异常返回 500，细节只写日志。
- 中间件是洋葱圈，必须 `await call_next` 并返回 response。
- CORS 只为浏览器存在；curl 不需要。
- 启动关闭用 `lifespan`，不要用已过时的 `on_event`。
- 鉴权、Session 用 Depends；全站日志、CORS 用中间件。
