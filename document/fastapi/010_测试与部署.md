# 010：测试与部署

> 本篇把“在 /docs 里点一下”升级成可重复的测试，并说明开发服务器和生产服务器的差别。
>
> 学习目标：会用 `TestClient` 写接口测试、在测试里覆盖数据库和依赖，知道 Uvicorn worker、环境变量、不要把 `--reload` 带上线。

---

## 一、我们要解决什么问题？

手工点文档有几个问题：

- 改了校验规则，不会自动提醒你旧请求已经 422。
- 登录、建书、再删除这一串步骤很难每次都走完整。
- 团队无法在提交代码时用同一套标准卡住回归。

FastAPI 基于 Starlette，自带对 ASGI 的测试客户端。测试里不需要先 `uvicorn` 起服务，而是在同一进程里把请求打进 `app`。

上线则是另一件事：开发时的 `--reload`、单进程、SQLite 文件，都不应该原样进生产。本篇只讲后端开发必须知道的那一层，不展开某云厂商的点击步骤。

安装：

```bash
pip install httpx pytest
```

较新的 `TestClient` 依赖 httpx。`fastapi[standard]` 开发环境通常已经有它们，没有就补上。

## 二、第一个测试

`tests/conftest.py`：

```python
import pytest
from fastapi.testclient import TestClient

from app.main import app


@pytest.fixture
def client():
    with TestClient(app) as c:
        yield c
```

`tests/test_health.py`：

```python
def test_health(client):
    response = client.get("/health")
    assert response.status_code == 200
    assert response.json() == {"status": "ok"}
```

项目根执行：

```bash
pytest -q
```

`TestClient` 的 `get` / `post` / `patch` / `delete` 和 httpx、requests 用法接近。`response.json()` 是已解析的 Python 对象。

用 `with TestClient(app)` 会触发 lifespan：建表、关引擎。不要每次测试都裸 `TestClient(app)` 却不进上下文，否则启动/清理不跑。

## 三、测试要隔离数据库

如果测试打到开发用的 `book.db`，你会一边测一边污染自己的数据，测试顺序也会互相影响。标准做法：测试用内存 SQLite，并覆盖 `get_db`。

```python
# tests/conftest.py
import pytest
from fastapi.testclient import TestClient
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from sqlalchemy.pool import StaticPool

from app.db import Base, get_db
from app.main import app
from app.models import book as book_model  # noqa: F401  注册表
from app.models import user as user_model  # noqa: F401


@pytest.fixture
def client():
    engine = create_engine(
        "sqlite://",
        connect_args={"check_same_thread": False},
        poolclass=StaticPool,
    )
    TestingSession = sessionmaker(bind=engine, autoflush=False, autocommit=False)
    Base.metadata.create_all(bind=engine)

    def override_get_db():
        session = TestingSession()
        try:
            yield session
            session.commit()
        except Exception:
            session.rollback()
            raise
        finally:
            session.close()

    app.dependency_overrides[get_db] = override_get_db
    with TestClient(app) as c:
        yield c
    app.dependency_overrides.clear()
```

`sqlite://` 加 `StaticPool`：内存库默认每个连接一份空库，连接池必须让所有 Session 共享同一份。

`app.dependency_overrides[原依赖] = 新函数` 是 FastAPI 专门给测试的口子。010 之后你还会用它假造 `get_current_user`，不必每次走登录。

测完 `clear()`，避免泄漏到下一个测试文件。

## 四、测 CRUD 和 422

`tests/test_books.py`：

```python
def _auth_headers(client):
    # 若 009 的注册接口可用：
    client.post(
        "/auth/register",
        json={"username": "alice", "password": "secret123"},
    )
    response = client.post(
        "/auth/login",
        data={"username": "alice", "password": "secret123"},
    )
    token = response.json()["access_token"]
    return {"Authorization": f"Bearer {token}"}


def test_create_and_get_book(client):
    headers = _auth_headers(client)
    created = client.post(
        "/books",
        json={"title": "FastAPI 入门", "author": "张三", "year": 2024, "price": 59},
        headers=headers,
    )
    assert created.status_code == 201
    book_id = created.json()["id"]

    detail = client.get(f"/books/{book_id}")
    assert detail.status_code == 200
    assert detail.json()["title"] == "FastAPI 入门"


def test_create_book_validation_error(client):
    headers = _auth_headers(client)
    response = client.post(
        "/books",
        json={"title": "x", "author": "y", "year": 999, "price": -1},
        headers=headers,
    )
    assert response.status_code == 422


def test_get_missing_book(client):
    response = client.get("/books/999")
    assert response.status_code == 404
```

注意登录用 `data=`（表单），创建图书用 `json=`（JSON）。这和 009 的坑对应，测试里写错会得到 422，不是 401。

断言优先看 **状态码**，再看关键字段。不要对整个 JSON 做一次 `==` 冻死所有字段，除非那就是契约测试。`id`、时间戳每次都会变。

## 五、覆盖依赖，跳过真实登录

测删除权限时，不必每次注册管理员。直接覆盖：

```python
from app.deps import get_current_user
from app.models.user import User


def test_admin_can_delete(client):
    admin = User(id=1, username="admin", hashed_password="x", role="admin")

    def fake_admin():
        return admin

    app.dependency_overrides[get_current_user] = fake_admin
    # 先插入一本书……再 delete
    app.dependency_overrides.pop(get_current_user, None)
```

覆盖 `get_current_user` 之后，`require_admin` 仍会跑（它 Depends 当前用户）。若 `require_admin` 也要换成假的，按需覆盖。测 403 时让 fake 返回 `role="user"`。

原则：

- 测登录本身：走真实 `/auth/login`。
- 测图书业务：覆盖用户依赖，把焦点留在书上。
- 测数据库约束：不要 mock 掉 Session，那是本测的对象。

## 六、异步测试

路径函数是 `async def`、内部 await 数据库时，仍可用同步 `TestClient`，它会在内部跑事件循环。也可以：

```python
import pytest
from httpx import ASGITransport, AsyncClient

from app.main import app


@pytest.mark.anyio
async def test_health_async():
    transport = ASGITransport(app=app)
    async with AsyncClient(transport=transport, base_url="http://test") as ac:
        response = await ac.get("/health")
    assert response.status_code == 200
```

学习阶段同步 TestClient 足够。全异步 SQLAlchemy 再上 AsyncClient。

## 七、开发与生产的启动差别

| | 开发 | 生产 |
|---|---|---|
| 命令 | `uvicorn app.main:app --reload` | `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4` |
| reload | 要 | 不要 |
| workers | 1 | CPU 核数附近，需实测 |
| 数据库 | SQLite 文件 / 内存 | PostgreSQL 等真正的服务 |
| 日志 | 终端 | 结构化日志 + 采集 |
| 密钥 | `.env` | 平台的密钥管理，不进镜像 |

`--reload` 会再拉起一个监视进程，行为、信号、内存都不适合生产。

`--workers 4` 是 4 个进程，各有一份 Python 内存。这就是内存字典方案彻底不可用的原因，也是 Session 不能放全局的原因。共享状态必须在数据库、Redis 里。

`host 0.0.0.0` 表示监听所有网卡，容器里通常需要。只在本机调试用 `127.0.0.1`。

前面还可以加 Nginx / Caddy 做 TLS 终止、静态文件、反向代理。FastAPI 进程自己也可以用 `--ssl-keyfile`，但证书续期更适合放在反向代理。

Gunicorn + UvicornWorker 是另一种常见写法：

```bash
gunicorn app.main:app -k uvicorn.workers.UvicornWorker -w 4 -b 0.0.0.0:8000
```

本质仍是多个 Uvicorn worker。能说清 “ASGI 应用 + worker 进程” 即可。

## 八、环境变量与配置

生产用环境变量注入，不要把 `.env` 打进 Docker 镜像。

```python
# app/config.py
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    database_url: str = "sqlite:///./book.db"
    secret_key: str = "dev-only-change-me"
    access_token_expire_minutes: int = 60
    cors_origins: list[str] = ["http://localhost:5173"]


def get_settings() -> Settings:
    return Settings()
```

测试里：

```python
from app.config import get_settings, Settings

app.dependency_overrides[get_settings] = lambda: Settings(
    database_url="sqlite://",
    secret_key="test-secret",
)
```

前提是路径和 db 模块通过 `Depends(get_settings)` 或等价方式读配置，而不是 import 时写死。008 若已在模块顶层 `create_engine(os.getenv(...))`，测试覆盖会困难一些——这也是 `create_app()` 工厂函数的价值：测试可以先改环境再创建 app。

## 九、Docker 最小形态

了解即可，按需使用。`Dockerfile`：

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY pyproject.toml .
RUN pip install --no-cache-dir .
COPY app ./app
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

配套 `docker-compose.yml` 里再加 PostgreSQL 服务，把 `DATABASE_URL` 指过去。镜像内不要 `--reload`，不要放 `.env` 真密钥。

健康检查用已经写好的 `GET /health`。编排系统（K8s、Compose）据此判断进程是否该摘掉。

## 十、上线前的短清单

1. `SECRET_KEY`、数据库密码来自环境，不在仓库。
2. `DEBUG` 类开关关闭；500 响应不包含 traceback。
3. CORS `allow_origins` 写具体前端域名。
4. `/docs` 是否对外暴露：内网 API 可开，公网考虑关掉或加保护。
5. 数据库用迁移，不用 `create_all` 当发布手段。
6. 有针对 401/403/404/409/422 的测试，不只测快乐路径。
7. worker 数 > 1 时，确认没有依赖进程内存的状态。
8. 时区、日志用 UTC 或明确时区，JWT `exp` 用 timezone-aware datetime。

这些不是 FastAPI 特有的，但 FastAPI 项目漏做的方式和别的后端一样。

## 十一、本篇小结

测试最小形状：

```python
def test_health(client):
    response = client.get("/health")
    assert response.status_code == 200
```

需要掌握的核心概念：

- `TestClient` 在进程内调用 app，不必先起 Uvicorn。
- 用 `dependency_overrides` 换数据库 Session、当前用户。
- 测试库和开发库分开，SQLite 内存库记得 `StaticPool`。
- 表单用 `data=`，JSON 用 `json=`。
- 生产去掉 `--reload`，用多 worker；共享状态放数据库。
- 配置走环境变量；`create_app()` 方便测试组装。
- `/health` 给探活用，鉴权不要挡它。

## 学完之后做什么？

按编号走到这里，你已经具备独立写一个小型 FastAPI 服务的能力：参数、模型、分层、数据库、登录、测试。接下来按需补，不必按顺序：

- Alembic 迁移
- 异步 SQLAlchemy
- Redis 缓存与限流
- 后台任务：`BackgroundTasks` 只适合很短的事；稍重的用 Celery / arq / Taskiq
- WebSocket
- 文件上传与对象存储
- OpenAPI 生成前端客户端

官方文档 <https://fastapi.tiangolo.com/> 适合当查阅手册。遇到具体参数时去查，比从头再读一遍更有效。你现在缺的不是更多 API 名字，而是把自己的图书项目改成一个真实业务，并补上测试。
