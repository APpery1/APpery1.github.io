# 004：响应模型与状态码

> 本篇把“函数 return 了什么就原样给客户端”变成可控制的出口，并写完内存版 CRUD。
>
> 学习目标：会用 `response_model`、HTTP 状态码、`HTTPException`，理解为什么 404 不该再返回 200。

---

## 一、我们要解决什么问题？

到上一篇为止，接口成功时都是 200，失败时有时返回 `{"error": "未找到图书"}`，也是 200。前端只能靠猜字段判断成败。HTTP 本身已经有语义：

| 状态码 | 含义 | 典型场景 |
|---|---|---|
| 200 | 成功，有响应体 | GET、PATCH 成功 |
| 201 | 已创建 | POST 成功 |
| 204 | 成功，无响应体 | DELETE 成功 |
| 400 | 请求本身不合理 | 业务规则失败（如重复书名） |
| 401 | 未认证 | 没带 token（009） |
| 403 | 已认证但没权限 | 普通用户删别人的资源 |
| 404 | 资源不存在 | id 不存在 |
| 409 | 冲突 | 唯一约束冲突 |
| 422 | 校验失败 | FastAPI / Pydantic 自动产生 |
| 500 | 服务器未处理异常 | 代码 bug |

另外，数据库里的对象常常比对外字段多：`hashed_password`、内部标记。必须有一层“出口过滤器”，避免多返回。

FastAPI 的做法是：

- 用 `response_model` 声明出口形状。
- 用 `status_code` 声明成功时的状态码。
- 用 `HTTPException` 声明失败。

## 二、`response_model`：出口过滤器

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class BookCreate(BaseModel):
    title: str
    author: str
    year: int = Field(ge=1400, le=2100)
    price: float = Field(gt=0)


class BookRead(BaseModel):
    id: int
    title: str
    author: str
    year: int
    price: float


@app.post("/books", response_model=BookRead)
def create_book(payload: BookCreate):
    return {
        "id": 1,
        **payload.model_dump(),
        "internal_note": "不要泄漏",
    }
```

函数虽然 return 了 `internal_note`，客户端实际拿到的 JSON **不会包含它**。FastAPI 用 `BookRead` 再过滤一遍。

这和“我 return 的 dict 正好是这些字段”不是一回事：

- 现在字段刚好对，不代表以后加字段还记得删。
- ORM 对象上可能有 relationship、密码哈希。
- 文档里的 Response schema 来自 `response_model`，不是来自你猜的 return。

也可以写返回值注解，效果接近：

```python
@app.post("/books")
def create_book(payload: BookCreate) -> BookRead:
    ...
```

较新的 FastAPI 会把 `-> BookRead` 当成响应模型。同时写 `response_model=` 和注解时，**装饰器参数优先**。团队里二选一即可，本系列用装饰器参数，看起来更明确。

列表：

```python
@app.get("/books", response_model=list[BookRead])
def list_books():
    return list(BOOKS.values())
```

## 三、响应模型的几个常用开关

```python
@app.get(
    "/books/{book_id}",
    response_model=BookRead,
    response_model_exclude_unset=True,
)
```

| 参数 | 作用 |
|---|---|
| `response_model_exclude_unset` | 没被赋值的字段不输出 |
| `response_model_exclude_none` | 值为 None 的字段不输出 |
| `response_model_exclude={"price"}` | 去掉某些字段 |
| `response_model_include={"id", "title"}` | 只留某些字段 |

`exclude` / `include` 适合临时裁剪。长期方案仍然是：**专门定义一个更小的模型**，例如列表接口用 `BookSummary`，详情用 `BookRead`。字段变少时文档更清楚，比在装饰器里藏 `exclude` 好维护。

```python
class BookSummary(BaseModel):
    id: int
    title: str
    author: str
```

## 四、成功时的状态码

```python
from fastapi import status


@app.post("/books", response_model=BookRead, status_code=status.HTTP_201_CREATED)
def create_book(payload: BookCreate):
    ...
```

写 `status_code=201` 也可以。用 `status.HTTP_201_CREATED` 是为了避免魔法数字，文档里也会显示 201。

DELETE 常返回 204，并且 **没有响应体**：

```python
from fastapi import Response, status


@app.delete("/books/{book_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_book(book_id: int):
    BOOKS.pop(book_id, None)
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

204 时不要 `return {"ok": True}`，部分客户端会困惑。用 `Response` 明确空 body。

注意：上面这版在 id 不存在时也 204。是否把“删一个不存在的资源”当成成功，团队要约定。REST 常见两种：

- 幂等：删两次都 204。
- 严格：第二次 404。

本篇示例采用严格：不存在就 404。

## 五、失败时请抛 `HTTPException`

```python
from fastapi import FastAPI, HTTPException, status

app = FastAPI()


@app.get("/books/{book_id}", response_model=BookRead)
def get_book(book_id: int):
    book = BOOKS.get(book_id)
    if book is None:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="未找到图书",
        )
    return book
```

客户端收到：

```json
{"detail": "未找到图书"}
```

状态码 404。`detail` 可以是字符串，也可以是 dict / list，FastAPI 会放进 JSON。

不要再 `return {"error": ...}` 并保持 200。前端最可靠的分支条件是状态码。

`HTTPException` 是控制流，不是没接住的 bug。007 会讲如何把它格式化成公司统一的 `{code, message, data}`。现在用框架默认即可。

业务冲突同样抛：

```python
if any(b["title"] == payload.title for b in BOOKS.values()):
    raise HTTPException(
        status_code=status.HTTP_409_CONFLICT,
        detail="书名已存在",
    )
```

校验类问题能用 Pydantic 表达的，继续放在模型里（自动 422）。模型表达不了、必须查现有数据的，用 `HTTPException`。

## 六、函数里动态决定状态码

装饰器上的 `status_code` 是**成功默认值**。少数接口要按情况返回 200 或 201，例如 upsert：

```python
from fastapi import Response, status


@app.put("/books/{book_id}", response_model=BookRead)
def upsert_book(book_id: int, payload: BookCreate, response: Response):
    if book_id in BOOKS:
        BOOKS[book_id] = {"id": book_id, **payload.model_dump()}
        response.status_code = status.HTTP_200_OK
        return BOOKS[book_id]
    BOOKS[book_id] = {"id": book_id, **payload.model_dump()}
    response.status_code = status.HTTP_201_CREATED
    return BOOKS[book_id]
```

把 `Response` 声明为参数，FastAPI 会注入，你改 `status_code` 即可。学习阶段每个接口固定一个成功码更简单，不必急着 upsert。

需要自定义响应头时也可以：

```python
response.headers["X-Book-Id"] = str(book_id)
```

## 七、内存版完整 CRUD

把 001–004 串起来，得到一个可以联调的小 API。数据在进程内存里，**重启服务就没了**。这是故意的：先把 HTTP 语义练熟，008 再换数据库。

```python
from typing import Annotated

from fastapi import FastAPI, HTTPException, Path, Query, Response, status
from pydantic import BaseModel, Field, field_validator

app = FastAPI(title="图书管理 API", version="0.4.0")

BOOKS: dict[int, dict] = {}
next_id = 1


class BookCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    author: str = Field(min_length=1, max_length=50)
    year: int = Field(ge=1400, le=2100)
    price: float = Field(gt=0)

    @field_validator("title", "author")
    @classmethod
    def strip_text(cls, value: str) -> str:
        stripped = value.strip()
        if not stripped:
            raise ValueError("不能为空")
        return stripped


class BookUpdate(BaseModel):
    title: str | None = Field(default=None, min_length=1, max_length=100)
    author: str | None = Field(default=None, min_length=1, max_length=50)
    year: int | None = Field(default=None, ge=1400, le=2100)
    price: float | None = Field(default=None, gt=0)


class BookRead(BaseModel):
    id: int
    title: str
    author: str
    year: int
    price: float


@app.get("/health")
def health():
    return {"status": "ok"}


@app.get("/books", response_model=list[BookRead])
def list_books(
    author: Annotated[str | None, Query()] = None,
    q: Annotated[str | None, Query(min_length=1, max_length=50)] = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
):
    items = list(BOOKS.values())
    if author:
        items = [b for b in items if b["author"] == author]
    if q:
        items = [b for b in items if q in b["title"]]
    return items[:limit]


@app.get("/books/{book_id}", response_model=BookRead)
def get_book(book_id: Annotated[int, Path(ge=1)]):
    book = BOOKS.get(book_id)
    if book is None:
        raise HTTPException(status_code=404, detail="未找到图书")
    return book


@app.post("/books", response_model=BookRead, status_code=status.HTTP_201_CREATED)
def create_book(payload: BookCreate):
    global next_id
    if any(b["title"] == payload.title for b in BOOKS.values()):
        raise HTTPException(status_code=409, detail="书名已存在")
    book = {"id": next_id, **payload.model_dump()}
    BOOKS[next_id] = book
    next_id += 1
    return book


@app.put("/books/{book_id}", response_model=BookRead)
def replace_book(book_id: Annotated[int, Path(ge=1)], payload: BookCreate):
    if book_id not in BOOKS:
        raise HTTPException(status_code=404, detail="未找到图书")
    book = {"id": book_id, **payload.model_dump()}
    BOOKS[book_id] = book
    return book


@app.patch("/books/{book_id}", response_model=BookRead)
def patch_book(book_id: Annotated[int, Path(ge=1)], payload: BookUpdate):
    stored = BOOKS.get(book_id)
    if stored is None:
        raise HTTPException(status_code=404, detail="未找到图书")
    stored.update(payload.model_dump(exclude_unset=True))
    return stored


@app.delete("/books/{book_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_book(book_id: Annotated[int, Path(ge=1)]):
    if book_id not in BOOKS:
        raise HTTPException(status_code=404, detail="未找到图书")
    del BOOKS[book_id]
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

建议在 `/docs` 按这个顺序点一遍：

```text
POST /books     → 201，记下 id
GET  /books     → 200，列表里有刚创建的
GET  /books/1   → 200
PATCH /books/1  → 只改 price
PUT  /books/1   → 必须带全字段
GET  /books/99  → 404
POST 同名        → 409
DELETE /books/1 → 204
DELETE /books/1 → 404
```

到这里，你已经会写一套符合常见 REST 习惯的 API。缺的是：公共逻辑还没抽（005）、代码还在单文件（006）、错误格式不统一（007）、数据不持久（008）、谁都能改（009）。

## 八、`JSONResponse` 什么时候用？

绝大多数时候 **不要** 自己构造 `JSONResponse`。`return dict / model` 加上 `response_model` 就够了。

需要绕过响应模型、或返回已经是 JSON 字符串时才用：

```python
from fastapi.responses import JSONResponse


@app.get("/raw")
def raw():
    return JSONResponse(content={"ok": True}, status_code=200)
```

同类还有 `PlainTextResponse`、`HTMLResponse`、`RedirectResponse`、`FileResponse`、`StreamingResponse`。文件下载、SSE、重定向才会用到它们。JSON API 主路径保持“return 模型”更干净。

## 九、本篇小结

出口三件套：

```python
@app.post("/books", response_model=BookRead, status_code=201)
def create_book(payload: BookCreate):
    ...

raise HTTPException(status_code=404, detail="未找到图书")
```

需要掌握的核心概念：

- `response_model` 过滤返回字段，并生成文档中的响应 schema。
- 创建用 201，删除用 204，找不到用 404，不要用 200 装失败。
- `HTTPException` 是给客户端看的错误，不是未捕获异常。
- PATCH 继续使用 `exclude_unset=True`。
- 内存 CRUD 只为练 HTTP；生产数据必须进数据库。
