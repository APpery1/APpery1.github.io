# 007：RAG 文档向量化与数据库准备

> 本篇对应当前项目中的 `app/rag/hash.py`、`app/rag/upload.py`、`app/rag/embeddings.py`、`app/rag/store.py`、`app/rag/update.py`、`app/ingest.py` 和 `app/config.py`。
>
> 学习目标：理解离线入库流水线——上传文本、用 MD5 检测变更、切块、embedding、写入向量库。问答怎么检索、怎么调用模型，见 `008`。

---

## 一、我们要解决什么问题？

到 `006` 为止，助手能接着聊天、记住用户、搜网页、改 Blender 场景。还缺一块：**已经写好的本地资料**，例如本仓库的 `DOCUMENT/*.md`。

用户问「长期记忆存在哪里？」时，模型不该凭印象编，而应先从本地文档里拿出相关段落。这就是 RAG（Retrieval-Augmented Generation）：**先检索，再生成**。

整条 RAG 分成两段，不要混在一次 `chain.invoke` 里做完：

```text
007 离线准备（本篇）
  文档 → 切块 → embedding → 写入向量库

008 在线问答
  问题 → 向量匹配 → 工具把段落交给模型 → 生成带出处的答案
```

入库是独立命令，不在每次对话里扫全盘。没跑过 ingest 时，`008` 的检索工具只能说「请先入库」。

默认**不**启用 RAG。没 ingest 时，CLI 行为和 `001`～`006` 一样。

---

## 二、`app/rag/` 各文件干什么？

RAG 是独立包，不再是单个 `app/rag.py`。按「准备知识库」和「回答问题」分开读：

| 文件 | 板块 | 本篇还是 008 | 一句话 |
|---|---|---|---|
| `hash.py` | MD5 工具 | 007 | 判断文件有没有改过，生成稳定块 ID |
| `upload.py` | 文本上传 | 007 | 把 md/txt 写入 `data/kb/`，扫描语料，切块 |
| `embeddings.py` | 向量化 | 007 | 调用 embedding 模型，文字 → 浮点向量 |
| `store.py` | 向量存储 | 007 | Chroma 或内存向量库落盘，按 source 覆盖 |
| `update.py` | 知识库更新 | 007 | 全量入库 / 单文件更新 / 删除过期来源 |
| `retrieve.py` | 向量匹配 | 008 | 按问题检索 top-k，格式化成工具文本 |
| `__init__.py` | 包出口 | 两篇 | 对外只暴露稳定函数名 |
| `__main__.py` | CLI | 007 | `python -m app.rag ingest \| upload` |
| `app/ingest.py` | CLI 薄封装 | 007 | `python -m app.ingest`，内部调用 `ingest_corpus` |

数据落在哪：

```text
DOCUMENT/             默认教材语料
data/kb/              用户上传目录
data/vectorstore/     向量库 + manifest.json（gitignore）
```

下面按流水线顺序讲准备阶段。

## 三、文本上传：`upload.py`

知识库的入口有两种：

1. 已经在仓库里的 `DOCUMENT/`，ingest 时直接扫描。
2. 运行期新增的资料，写入 `data/kb/`。

`upload_text(content, filename, dest_dir)` 把一段字符串写成文件；`upload_file(src, dest_dir)` 复制本地已有文件。两者都做安全检查，风格对齐 `003` 的 `write_file`：

- 只允许 `.md` / `.txt`
- 文件名必须是相对路径，禁止 `..`
- 只接受 UTF-8，默认不超过 1MB
- 实际路径必须落在目标目录内

扫描用 `iter_corpus_files()`。切块也放在这个文件里：上传进来的是「一篇文章」，入库需要的是「带元数据的小段」。

### 为什么要切块？

模型上下文有限，整份 `005_compact与hook.md` 一次塞进去既贵又吵。切成小段后，检索只送最相关的几块。

约定：

- Markdown 按标题切开，避免把 `004` 的表格和后一节粘在一起。
- 其它文本用递归字符切分（先按段落，再按句）。
- **按字符计数**，不要按英文 token 经验值硬套。中文默认 `chunk_size=800`，`chunk_overlap=150`。

每一块的 metadata：

| 字段 | 例子 | 用途 |
|---|---|---|
| `source` | `DOCUMENT/004_长期记忆.md` | 回答时引用 |
| `title` | `004：跨会话长期记忆` | 给人看 |
| `chunk_index` | `2` | 同一文件内的顺序 |
| `hash` | 文件 MD5 | 判断要不要重入库 |

`source_key()` 尽量用相对项目根的 posix 路径，这样 Windows / Linux 上的出处长得一样。

## 四、MD5 工具：`hash.py`

重复 ingest 同一份没改过的文档，不该再付一次 embedding 费用，也不该让向量库里堆两份。

`hash.py` 只做变更检测，**不是**安全哈希（密码、签名不要用它）：

| 函数 | 作用 |
|---|---|
| `md5_bytes` / `md5_text` / `md5_file` | 内容指纹 |
| `chunk_id(source, index)` | 用 source 的 MD5 前缀生成稳定块 ID |

更新流程里的用法：

```text
读文件 → md5_file
  与 manifest 里记录的 hash 相同 → 跳过
  不同 → 按旧 chunk_id 删掉旧向量，再写入新块
```

`chunk_id` 必须稳定：同一 `source` 第 3 块，两次入库的 id 相同，`store.delete(ids=...)` 才能对准。

---

## 五、Embedding：`embeddings.py`

embedding 把一段文字变成一组浮点数。语义相近的段落在空间里距离更近。

「长期记忆存在哪里」和「JSON 文件按 user_id 持久化」用词不同，关键词可能对不上，向量往往能对上。这是 RAG 相对 `004` 里 `search_memory` 关键词打分的意义。

聊天模型（`MODEL_NAME`）和 embedding 模型必须分开配置。很多兼容 OpenAI 协议的服务，两个名字不是同一个。`build_embeddings()` 走现有 `OPENAI_API_KEY` / `OPENAI_BASE_URL`，用的是 `EMBEDDING_MODEL`。

本文件很短，故意单独放：入库和检索都要 embedding，但不该把 OpenAI 客户端细节散进 `store.py` / `update.py`。

测试禁止打真实 embedding API，注入假的 `HashEmbeddings`。

## 六、向量存储：`store.py`

本项目是本地 CLI，长期记忆已经是文件落盘，向量库也要能重启后还在。

| 方案 | 优点 | 缺点 | 本项目 |
|---|---|---|---|
| Chroma | LangChain 文档多、自带持久化 | 额外依赖，部分 Python 版本不好装 | **优先** |
| `InMemoryVectorStore` 落盘 | `langchain_core` 自带 | 大规模语料不如专用库 | **未安装 Chroma 时的默认** |

`open_knowledge_index()` 先尝试 Chroma，失败则 `InMemoryVectorStore.dump` 到 `data/vectorstore/memory.json`。

`KnowledgeIndex` 包在 VectorStore 外面，多做三件事：

1. **按 source 覆盖**：`replace_source` 先删旧 id，再写入新块。
2. **manifest.json**：记录每个 source 的 MD5、块 id、块数。
3. **检索入口**：`search(query, k=...)`。内存库用纯 Python 余弦，避免强绑 numpy；Chroma 走它自己的相似度。

`data/` 已在 `.gitignore`。可选安装：

```bash
pip install -e ".[rag]"   # langchain-chroma
```

不要按 `user_id` 给文档建库。`004` 的事实才按用户隔离；`DOCUMENT/` 是共享教材。也不要把短期 history、工具中间态、compact 摘要写入索引。

## 七、知识库更新：`update.py`

这是准备阶段的调度器，不直接切块、不直接调 embedding API。

| 函数 | 作用 |
|---|---|
| `ingest_corpus` | 扫描 `DOCUMENT/` + `data/kb/`，全量同步 |
| `update_path` | 只更新一个文件，不动其它来源 |
| `remove_source` | 按 source 键删一条 |
| `upload_and_update` | 先上传到 `data/kb/`，再立刻入向量库 |

全量同步的步骤：

```text
列出当前语料文件
  每个文件算 MD5
    与 manifest 相同 → skipped
    不同 → 切块 → replace_source → ingested
manifest 里有、磁盘上没有 → delete_source → deleted
```

`IngestReport` 统计扫描 / 写入 / 跳过 / 删除 / 总块数，给 CLI 打印。

单文件更新走 `update_path`，**不会**把知识库里其它文档清掉。适合「刚 upload 了一篇 notes.md」。

## 八、配置与运行

`app/config.py` 里和本篇有关的项：

| Python 字段 | 环境变量 | 默认 | 作用 |
|---|---|---|---|
| `rag_docs_path` | `RAG_DOCS_PATH` | `DOCUMENT` | 默认语料目录 |
| `rag_extra_path` | `RAG_EXTRA_PATH` | `data/kb` | 上传目录 |
| `rag_persist_path` | `RAG_PERSIST_PATH` | `data/vectorstore` | 索引落盘 |
| `embedding_model` | `EMBEDDING_MODEL` | `text-embedding-ada-002` | 向量模型，不复用 `MODEL_NAME` |
| `rag_chunk_size` | `RAG_CHUNK_SIZE` | `800` | 切块字符数 |
| `rag_chunk_overlap` | `RAG_CHUNK_OVERLAP` | `150` | 块之间重叠 |

`RAG_ENABLED` / `RAG_TOP_K` 是问答开关和检索条数，见 `008`。

入库需要 `OPENAI_API_KEY`（embedding 也走它）：

```bash
python -m app.ingest
python -m app.rag upload notes.md
```

预期打印扫描了多少文件、写了多少块、索引在哪。第一版只收 `.md` / `.txt`，不做 PDF、网页整站、源代码全库。

## 九、测试覆盖了什么？

`tests/test_rag.py` 里属于本篇的部分：

- MD5：内容一变，摘要就变。
- 上传：写入 `data/kb` 风格的目录；`../escape.md` 被拒绝。
- 切块：带 `##` 的 md，`metadata.source` 正确。
- 覆盖入库：同一文件 ingest 两次，块数不翻倍。
- 删除：磁盘文件消失后，下一次 ingest 会 `deleted == 1`。
- `upload_and_update`：上传后立刻能按内容检索到。

Embedding 全是假向量，不打真实 API。需要文件系统时用 pytest 的临时目录。

## 十、本篇小结

准备一条可检索的知识库，可以看成：

```text
upload.py   拿到干净的 md/txt
     ↓
hash.py     用 MD5 决定跳过还是重算
     ↓
split_text  切成带 source 的块
     ↓
embeddings  文字 → 向量
     ↓
store.py    写入 data/vectorstore/
     ↓
update.py   统计报告，删除过期来源
```

记住：

- 入库是离线步骤，对话链不负责扫盘。
- MD5 管「有没有改过」，不管安全。
- 聊天模型和 embedding 模型分开配置。
- 向量库按文档 source 覆盖，不按 `user_id` 隔离。
