# 006：MCP 工具

> 本篇对应当前项目中的 `app/MCP.py`、`app/main.py`、`app/chain.py` 和 `app/config.py`。
>
> 学习目标：理解 MCP 是什么、它和 `003` 里本地 `@tool` 的差别，以及本 CLI 如何把 [blender-mcp](https://github.com/ahujasid/blender-mcp) 发现成 LangChain 工具，再送进现有的工具循环。

---

## 一、我们要解决什么问题？

`003` 里的工具是**写在本仓库里的 Python 函数**：搜索、读写文件、沙箱、HTTP、计算器、SQL、记忆。它们和 CLI 进程跑在一起，改工具就要改 `app/tool.py`。

如果能力在**另一个程序**里——例如正在运行的 Blender——就不能再 `@tool def 创建一个立方体()` 了事。那个立方体必须由 Blender 自己创建。

这时需要一种约定：

1. 外部程序以标准方式公布「我有哪些工具、参数长什么样」。
2. 我们的 CLI 当客户端，把这些说明书转成 LangChain 的 `BaseTool`。
3. 模型决定调用后，请求发到外部程序，由它真正执行。

这套约定就是 **MCP（Model Context Protocol）**。本项目接入的是 Blender 的 MCP 服务：[ahujasid/blender-mcp](https://github.com/ahujasid/blender-mcp)（PyPI 现名 `mcp-for-blender`，`uvx blender-mcp` 仍然可用）。

相关文件：

```text
app/MCP.py       拼连接参数、发现工具、转成同步 LangChain Tool
app/main.py      --blender / BLENDER_MCP_ENABLED 时启动并在退出时关闭
app/chain.py     extra_tools 并进现有 run_tool_loop
app/config.py    主机、端口、uvx 命令、超时
app/tool.py      本地工具；MCP 工具不写在这里
```

默认**不**启动 MCP。没装 Blender、没开插件时，CLI 行为和 `001`～`005` 一样。

---

## 二、MCP 是什么？

MCP 是给「语言模型 ↔ 外部能力」用的开放协议，常见传输是：

| 传输 | 典型场景 | 本项目 |
|---|---|---|
| **stdio** | 客户端拉起一个本地子进程，用标准输入输出说话 | blender-mcp |
| HTTP / SSE | 已经在跑的远程 MCP 服务 | 未使用 |

三个角色不要混：

```text
MCP 宿主 / 客户端     本项目 CLI（发现工具、把调用转给服务）
MCP 服务器            uvx blender-mcp 子进程（实现协议）
真正干活的应用        Blender +「MCP for Blender」插件（改场景）
```

对模型来说，MCP 工具和 `@tool` 长得一样：都有 `name`、`description`、参数 schema。差别在**执行发生在哪**：

```text
本地工具：  模型 → run_tool_loop → 本进程里的 Python 函数
MCP 工具：  模型 → run_tool_loop → MCP 客户端 → blender-mcp → Blender 插件
```

所以 `003` 的工具循环可以复用。本篇只多了「启动 MCP 服务、把远程工具适配成 BaseTool」这一层。

---

## 三、blender-mcp 的两段连接

官方架构是两跳，不是一跳：

```text
本 CLI
  │  stdio（JSON-RPC / MCP）
  ▼
uvx blender-mcp          ← MCP 服务器，默认命令
  │  TCP socket
  ▼
Blender 插件              ← 默认 localhost:9876
  │
  ▼
bpy：建物体、改材质、执行脚本……
```

只启动 CLI、不点 Blender 侧的 **Start MCP Server**，MCP 进程能起来，工具一调用就会失败。  
只开插件、CLI 不加 `--blender`，模型根本看不到 Blender 工具。

插件负责在 Blender 里听端口；`uvx blender-mcp` 负责对外讲 MCP。本仓库**不内嵌** Blender 插件源码，只当 MCP 客户端。

上游能力概览（具体名字以 `list_tools` 当时返回为准）：

- 查询场景 / 物体
- 创建、修改、删除对象与材质
- 在 Blender 里执行 Python（`bpy`）
- 导出场景
- 可选：Poly Haven、Sketchfab、Poly Pizza、生成式 3D 等（插件面板里打开）

`execute_blender_code` 能在 Blender 里跑任意 Python，和 `003` 的 `code_interpreter` 不是同一个沙箱。用之前先保存 `.blend`。

## 四、本项目怎么接到 CLI 上

### 1. 启动时发现工具

`app/main.py` 在组链之前，可选地拉起 MCP：

```python
if args.blender or settings.blender_mcp_enabled:
    from app.MCP import BLENDER_MAX_TOOL_ROUNDS, BlenderMCP

    mcp = BlenderMCP(settings)
    extra_tools = mcp.start()
    max_tool_rounds = BLENDER_MAX_TOOL_ROUNDS
```

`BlenderMCP.start()` 内部：

1. 按 Settings 拼出 stdio 连接（命令、参数、传给子进程的环境变量）。
2. `langchain-mcp-adapters` 的 `MultiServerMCPClient.get_tools()` 向服务器要工具列表。
3. 每个工具包一层同步 `invoke`（见第六节）。
4. 返回 `list[BaseTool]`，作为 `build_chain(..., extra_tools=...)`。

进程退出时 `finally: mcp.close()`。当前实现里，适配器默认**每次工具调用新建一次 stdio 会话**，`close()` 主要是清掉引用。

### 2. 和本地工具并进同一条链

`app/chain.py`：

```python
tools = [*get_tools(settings, memory_store=store), *extra]
```

有 `extra_tools` 时会追加系统提示：建模、改材质、改物体或执行 `bpy` 前，先看当前场景；并提醒插件必须已 Start。

工具循环仍是 `003` 的 `run_tool_loop`。Blender 场景往往要多轮（先查场景再创建再调材质），因此启用 MCP 时把上限从 8 提到 `BLENDER_MAX_TOOL_ROUNDS = 16`。

一次「在场景里加红色立方体」可能是：

```text
第 1 次模型调用 → get_scene_info
执行 MCP 工具，Blender 返回场景摘要
第 2 次模型调用 → 创建立方体 / 执行 bpy
第 3 次模型调用 → 自然语言：「已经加了一个红色立方体」
```

对 `run_tool_loop` 来说，这和调用 `calculator` 没有区别，只是 `selected.invoke(...)` 最终打到了 Blender。

### 3. 为什么单独放 `app/MCP.py`

本地工具是函数；MCP 工具是**连接 + 发现 + 适配**。把 uvx、环境变量、超时、异步转换堆进 `tool.py` 会和 `003` 的主线缠在一起。`MCP.py` 只做客户端，不定义「创建一个立方体」这种业务函数——那些由 blender-mcp 公布。

## 五、连接参数和配置

`blender_connection(settings)` 产出适配器要的字典：

```python
{
    "transport": "stdio",
    "command": resolve_mcp_command(settings.blender_mcp_command),  # 默认 uvx
    "args": parse_mcp_args(settings.blender_mcp_args),            # 默认 ["blender-mcp"]
    "env": blender_server_env(settings),
}
```

传给 **blender-mcp 子进程**的环境变量与上游 README 对齐：

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `BLENDER_HOST` | `localhost` | 插件 socket 地址 |
| `BLENDER_PORT` | `9876` | 插件端口 |
| `BLENDER_MCP_SAFE_MODE` | 关 | 设为 `1` 时校验将在 Blender 里执行的脚本 |
| `DISABLE_TELEMETRY` | 本项目默认开 | 关闭 blender-mcp 遥测 |

CLI / `.env` 对应关系：

| Python 字段 | 环境变量 | 说明 |
|---|---|---|
| `blender_mcp_enabled` | `BLENDER_MCP_ENABLED` | `true` 时不必传 `--blender` |
| `blender_mcp_command` | `BLENDER_MCP_COMMAND` | 可执行文件，默认 `uvx` |
| `blender_mcp_args` | `BLENDER_MCP_ARGS` | `blender-mcp`，或 `blender-mcp --port 9877`，或 JSON 数组 |
| `blender_host` | `BLENDER_HOST` | 同上，再写入子进程 env |
| `blender_port` | `BLENDER_PORT` | 整数端口 |
| `blender_mcp_safe_mode` | `BLENDER_MCP_SAFE_MODE` | 安全模式 |
| `blender_mcp_disable_telemetry` | `BLENDER_MCP_DISABLE_TELEMETRY` | 默认 `true` |
| `blender_mcp_timeout` | `BLENDER_MCP_TIMEOUT` | 发现工具的超时，默认 60 秒 |

`BLENDER_MCP_ARGS` 两种写法：

```env
BLENDER_MCP_ARGS=blender-mcp --port 9877
BLENDER_MCP_ARGS=["mcp-for-blender", "--port", "9877"]
```

Windows 上 GUI 启动的进程经常找不到 `uvx`。可把 `BLENDER_MCP_COMMAND` 设成 `uvx` 的绝对路径（`where uvx`）。`resolve_mcp_command()` 会先 `shutil.which`。

`.env` 示例：

```env
# BLENDER_MCP_ENABLED=true
# BLENDER_MCP_COMMAND=uvx
# BLENDER_MCP_ARGS=blender-mcp
# BLENDER_HOST=localhost
# BLENDER_PORT=9876
```

## 六、异步 MCP 工具如何在同步 CLI 里调用

`langchain-mcp-adapters` 给出的工具以 **ainvoke / 协程** 为主。本项目的 `run_tool_loop` 是同步的 `selected.invoke(...)`（见 `003`）。

`app/MCP.py` 里 `_as_sync_tool` 再包一层：

```python
def _run(**kwargs):
    return asyncio.run(tool.ainvoke(kwargs))

return StructuredTool.from_function(
    name=tool.name,
    description=tool.description or tool.name,
    args_schema=getattr(tool, "args_schema", None),
    func=_run,
    coroutine=_arun,
)
```

名字、描述、参数 schema 保持 MCP 服务器提供的原样，模型看到的仍是 blender-mcp 的说明书。同步路径走 `asyncio.run`，以便现有 LCEL 链不用改成 `ainvoke`。

发现工具本身也是异步的，所以 `load_blender_tools()` 用 `asyncio.run(_load_blender_tools(...))`，并用 `asyncio.wait_for(..., timeout=...)` 避免 `uvx` 卡住时 CLI 一直挂起。

依赖：`langchain-mcp-adapters>=0.1.0,<0.2.0`（与当前 LangChain 0.3 匹配）。未安装时会提示 `pip install langchain-mcp-adapters`。**不要**把适配器升到 0.3.x，那一支需要 LangChain 1.x。

## 七、使用步骤

1. 安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，确认终端能运行 `uvx`（不要用 `pip install uv` 凑合）。
2. 安装并启用插件：

```bash
uvx blender-mcp install-addon
```

Blender：**Edit → Preferences → Add-ons** → 启用 **Interface: MCP for Blender**。

3. 3D 视图按 `N` → **MCP for Blender** → **Start MCP Server**（默认 `localhost:9876`）。
4. 启动本 CLI：

```bash
python -m app.main --blender "在场景里加一个红色立方体"
python -m app.main --blender
```

或 `.env` 里 `BLENDER_MCP_ENABLED=true`。

成功时会打印类似：

```text
已连接 Blender MCP（localhost:9876），工具 N 个。
```

交互模式的启动行会带「已连接 Blender MCP」。之后可以继续用 `003` 的本地工具（搜索、写文件、记忆等），它们和 Blender 工具挂在同一条链上。

同一时刻只跑**一个** MCP 客户端去连这套 blender-mcp。Cursor / Claude Desktop 如果已经占着同一套服务，不要再叠一个本 CLI。

## 八、和 `003` 本地工具怎么分工

| | `app/tool.py` | `app/MCP.py` |
|---|---|---|
| 谁定义工具 | 本仓库 | blender-mcp 服务器 |
| 何时出现 | 每次 `build_chain` | 仅 `--blender` 或环境变量打开 |
| 失败时 | 单个工具返回错误字符串 | 启动失败则整个 CLI 起不来（显式要求了 MCP） |
| 安全边界 | 工作区、SQL 禁 ATTACH、HTTP 只允许 http(s) | 取决于插件；代码执行发生在 Blender 进程 |

模型要「算一道题、写个 txt、记住我喜欢绿茶」→ 本地工具。  
模型要「场景里加个立方体、把立方体弄成金属红」→ Blender MCP。

不要在 `tool.py` 里再写一套 `create_cube`。MCP 的价值就是：**能力跟着 Blender 升级，CLI 只负责发现和转发**。

## 九、安全与限制

1. **插件 socket 没有鉴权**。默认只绑 `localhost`。不要把 `BLENDER_HOST` 指到公网机器，除非你清楚谁能连上那个端口。
2. **在 Blender 里执行代码 ≈ 操作你的整份工程**。先存盘。本项目默认 `blender_mcp_disable_telemetry=true`；若要限制脚本能力，打开 `BLENDER_MCP_SAFE_MODE`。
3. **发现工具会拉起 `uvx`**，第一次可能下载包，所以有 60 秒超时。
4. **每次调用可能新开 stdio 子进程**，会比本地 `@tool` 慢。这是适配器默认行为，换持久 session 需要处理「同步 invoke 和后台事件循环」的冲突，教学脚手架里没有做。
5. Compact（`005`）在工具消息还在飞时会跳过压缩，避免拆开 MCP 的 `tool_calls` / `ToolMessage` 配对。这一点对 Blender 的多轮调用同样重要。

## 十、测试覆盖了什么？

`tests/test_mcp.py` **不**启动真实 Blender，只锁定协议边界：

- `BLENDER_MCP_ARGS` 支持 shell 拆分和 JSON 数组。
- 默认连接是 `stdio` + `uvx` + `blender-mcp`，env 里带 `BLENDER_HOST/PORT`，默认关闭遥测。
- `safe_mode` 会写成 `BLENDER_MCP_SAFE_MODE=1`。
- `load_blender_tools` 走 `MultiServerMCPClient.get_tools(server_name="blender")`；缺适配器时有明确错误。
- `build_chain(extra_tools=[假的 get_scene_info])` 能走完 `run_tool_loop`，证明 MCP 工具和本地工具是同一套循环。

## 十一、以后可以怎么换？

1. 把 `BlenderMCP` 换成任意 stdio MCP：改 `command` / `args`，不必改 `run_tool_loop`。
2. 若 MCP 服务已是 HTTP，把 `blender_connection` 的 `transport` 换成适配器支持的 `http` / `sse`。
3. 需要更低延迟时，在后台事件循环里保持一条持久 `ClientSession`，同步 `invoke` 用 `run_coroutine_threadsafe` 投递过去。
4. 多个 MCP 服务可以放进同一个 `MultiServerMCPClient({...})` 字典，用 `tool_name_prefix=True` 避免重名。

对学习阶段，先记住这张图就够了：

```text
003 的本地工具 = 本进程里的函数
006 的 MCP 工具 = 别人进程里的函数，用协议发现和调用
二者在模型眼里都是 Tool，在 run_tool_loop 里走同一条路
```
